# Bug list, Oct 25 (web browser pass)

Found by reading [[gotchas]] and [[human-todo]], then running the app on web (iPhone-size viewport) with the dev test account. Not a device test: [[human-todo]] sections B to D still need two phones. Fixed items are noted in [[current-work]].

- **Expense live updates could die if migration 010 wasn't run** (my change): settlements shared a realtime channel with expenses. Now separate (`ExpenseContext.tsx`). See [[gotchas]].
- **Trip Summary lied when data failed to load**: showed "Nothing on the list yet" / "0 activities" when the checklist or itinerary couldn't load; now says "Couldn't load".
- **Trip Summary "Everyone's settled up" for a one-person trip**, with a chevron that only went back; now "Nothing to settle", and the row only links when payments remain.

- **Fixed in the second pass (audit follow-ups), uncommitted:**
  - Expenses of someone who left the trip can be renamed again; only changing payer, amount or split re-runs the member check (`011_audit_fixes.sql`).
  - Two organizers leaving at once can no longer leave a trip with none (trip row lock in `keep_an_organizer`, `011`).
  - Only the person who was paid (or an organizer) can record a payment; either side can still undo (`011`, `SettlementModel.canRecord`, Budget screen).
  - Confirm dialogs now work on web via `window.confirm` (`utils/confirm.ts`).
  - Payments cache is only written after a successful fetch (`ExpenseContext.tsx`).
  - Apple HIG skill files untracked and git-ignored (still on disk): `git rm --cached`, `.gitignore`.
